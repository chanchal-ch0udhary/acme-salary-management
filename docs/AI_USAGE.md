# How AI was used

The brief asks us to use AI tools and to be careful about quality. This page is an honest record.

**Tool:** Claude Code (an AI coding agent) working in the project folder: reading the brief, writing files, running the tests and a real browser, and committing.

## How the work was done

1. **Read the brief, write the requirements first.** `docs/REQUIREMENTS.md` (goal, features, what is left out and why) is the first commit.
2. **Rails skeleton.** Rails could not run on the author's Windows PC at first (a Windows security policy blocked Ruby), so the skeleton was generated by `rails new` in a GitHub Actions job on Linux. Later WSL2 was set up and everything was run locally.
3. **Backend in small steps**, each with specs and its own commit: models, statistics, API, seed script.
4. **Frontend.** The React screens were written first against a small Node API, then moved to this repository and re-pointed at the Rails API (field names changed to Rails-style `snake_case`).
5. **Verify.** Ran RSpec, ran the real app with 10,000 employees, and recorded the demo video from a real browser run.

## Prompts used (shortened)

| Step | Prompt |
|---|---|
| Plan | "Read the assessment. Propose scope and what to leave out for an HR salary tool with 10,000 employees. Write a one-page requirements doc first." |
| Rails | "Build a Rails 8 API with SQLite. Models Employee and SalaryChange. Salary is a whole number. Currency comes from the country. A salary change needs a reason and writes history in one transaction. Keep the code simple and easy to read." |
| Insights | "Write median, percentiles, breakdown, distribution and pay gap as plain Ruby classes that can be tested with hand-made rows. Hide the pay gap when a gender group has fewer than 5 people." |
| Seed | "Seed script with 10,000 repeatable fake employees across 12 countries with realistic pay and salary history." |
| Specs | "Write RSpec model, service and request specs. Include SQL injection, CSV formula injection, paging limits and the inactive-employee rule." |
| UI | "React + MUI dashboard, employee list with filters in the URL, employee page with history, salary dialog." |

## Choices made by the author (not AI defaults)

- **Rails + RSpec**, because that is the author's stack and the brief prefers the language of the role. Simple code over clever code.
- **Scope**: login, payroll, bonus, live exchange rates and background jobs are left out on purpose.
- **Salary change = its own action** with reason and date; the history can not disagree with the salary.
- **Compare in USD** (stored `salary_usd`), because 2,400,000 INR is not more money than 150,000 USD.

## Problems found while checking the AI's work

| Found by | Problem | Fix |
|---|---|---|
| Running the specs | One spec created the employee inside the `expect` block, so it counted the first history row | Create the employee before counting |
| Looking at the running dashboard (earlier Node version) | Country labels showed as `LUS`, `LAU` | Label helper fixed |
| CI | A number format differed between Node versions (`$85K` vs `$85.00K`) | Made the format explicit |
| First plan | The backend was first written in Node, which did not match the role | Rebuilt from scratch in Rails in a new repository |
| Tooling | Ruby 4.0 on Windows could not install gems | Used Ruby 3.4 inside WSL2 |

## What AI did not decide

What to leave out, which trade-offs to accept, and the final review of every commit. AI wrote fast; the author is responsible for understanding and defending the code (see the author's own notes for the interview).
